Truy hồi giai đoạn đầu: lọc authorizedDocumentIds và active version trước khi xếp hạng cosine chính xác. Python không có credential vào database nghiệp vụ.

Quan hệ chính trong database nghiệp vụ

  • subjects.id → topics.subject_id và documents.subject_id
  • users.id → owner của Personal Document, Note, Plan và Attempt
  • quizzes.id → Questions và Attempts; attempts.id → Answers
  • users.id + topics.id → Content Progress và Topic Mastery ở hai bảng riêng

Nối hai database bằng contract

Java gửi documentId, documentVersion và scope được phép qua internal API. Python lưu cùng ID trong bảng vector để index/truy hồi. Đây là tham chiếu logic, không có foreign key xuyên database. Java poll job để đổi trạng thái UPLOADING → PENDING_INDEX → INDEXING → READY/FAILED; khi xóa, chuyển DELETING trước khi deindex và xóa file.
